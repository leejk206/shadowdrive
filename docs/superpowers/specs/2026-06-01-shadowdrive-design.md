## 1. 한 줄 컨셉

고정된 광원 앞에서 **물체를 움직이고 회전**시켜 벽에 드리운 **그림자를 도로로 만들고**, 일정 추력으로
스스로 달리는 **자동차가 목표 지점에 도달**하도록 길을 설계하는 2.5D 공간 추론 퍼즐.

핵심 정체성: **"빛과 그림자로 길을 설계 → 출발시켜 검증"** — 타이밍 조작이 아닌 **정적 공간 추론** 퍼즐.

## 3. 코어 루프 & 시야 모델

### 3.1 코어 루프 (Plan → Go)

1. **로드** — 고정 광원 / 고정 오클루더 / 가동 오클루더 / 시작 패드의 자동차 / 목표 패드.
2. **PLAN** — 자동차 정지. 플레이어가 가동 물체를 드래그(이동) + 회전. 그림자가 **실시간 미리보기**로 갱신.
3. **GO** — "출발" 입력 → 그림자 상태 **고정(freeze)** → 자동차가 일정 추력으로 좌→우 주행, 중력 적용, 그림자 표면 위 주행.
4. **판정** — 목표 도달 = CLEAR / void 구간 추락·진행 불가 = FAIL → 즉시 PLAN 복귀(**물체 배치 유지**).

> GO 단계 중 그림자는 **불변**. 이 규칙이 "동적 그림자 → 콜라이더"라는 최대 기술 리스크를 구조적으로 제거.

### 3.2 시야/차원 모델 — 2.5D 측면 벽 투영

- 카메라: 벽면 정면 고정, **직교 투영(orthographic)**. heightfield와 화면이 1:1 대응(판정·시인성 일관성).
- 자동차는 **뒤 벽 평면 위 2D 경로**를 따라 좌→우 주행.
- 게임 로직에 영향을 주는 것은 **벽에 맺힌 그림자뿐**. 3D 물체끼리의 충돌은 시뮬레이션하지 않음.

## 4. 시스템 정의

### 4.1 광원
- **방향광(directional)**: 평행 광선 → 그림자 크기 = 물체 크기 동일. 초반 학습용. **L1 전용.**
- **점광원(point)**: 발산 광선 → 광원 쪽으로 옮기면 그림자 확대, 벽 쪽이면 축소. **빛 기하 = 길이 제어**의 근원. **L2부터 해금·주력.**
- 광원은 레벨당 1개, 위치·타입 고정. 플레이어 조작 불가.

### 4.2 투영면(벽) / 시작·목표
- 벽 = 고정 2D 평면. 좌측 **시작 패드**(자동차 초기 위치), 임의 위치 **목표 패드**. 패드는 항상 존재하는 고정 발판(그림자 아님).

### 4.3 오클루더
- 형태: **convex 프리미티브만** — 막대(직육면체), 원반(실린더), 삼각 프리즘, L-블록(두 convex 합). 비-convex 단일 메시 금지.
- **가동 오클루더**: PLAN에서 이동+회전 가능. 이동은 광원-벽 사이 볼륨으로 클램프.
- **고정 오클루더**: 위치·회전 잠금.
- **role 지정**: 각 오클루더는 레벨 데이터에서 `role: "floor" | "ceiling"`. floor=바닥 도로, ceiling=천장 장애물.
- **단일 레이어 제약**: 가동 오클루더는 깊이 축에서 서로 가리지 않도록 레벨 디자인 시 보장. 3D 물체 충돌 미시뮬.

### 4.4 그림자 → 콜라이더 추출 (**1D upper/lower envelope**, CSG union 미사용)

- 각 오클루더 정점을 광원 기준으로 벽 평면에 투영 → 벽 평면상 **convex 그림자 폴리곤** 집합.
- **일반 polygon union(CSG) 사용 안 함.** 최종 표현이 1D heightfield이므로 envelope으로 충분하고 더 견고하다:
  - **floor heightfield** `h(x)` = x 샘플마다 `role:"floor"` 그림자들의 **상단 y의 max**. 미커버 = `void`.
  - **ceiling heightfield** `c(x)` = x 샘플마다 `role:"ceiling"` 그림자들의 **하단 y의 min**. 미커버 = `∞`(천장 없음).
- 자동차 콜라이더 = `h(x)`(주행면) + `c(x)`(머리 위 제약). 오버행/구멍 비표현(단일 레이어 + envelope으로 구조적 보장). 깊은 골=h(x) 급강하.
- **채택 근거(2026-06-01 확정)**: ① 비교 연산뿐이라 글리치 최소 → "브라우저 미실행 0점" 룰에 대한 견고성 확보. ② 투영 행렬+envelope을 **직접 구현·서술** → 기술적 우수성 내러티브가 외부 CSG 라이브러리 인용("기타 사용 기능")보다 강함.
- **Report 서술 표현**: "투영된 convex 실루엣의 샘플링축 상/하 envelope (polygon union의 1D 특수화)".

### 4.5 자동차
- 모델: 폭 1.0 × 높이 0.5 (월드 유닛, 튜닝 파라미터).
- **일정 추력**: 평지 등속(기준 v0 = 4.0 unit/s). 경사에서 중력 성분으로 가감속.
- **중력**: g = 9.8 unit/s² (스케일 튜닝 가능).
- **등판 한계각**: 35°. 초과 경사는 미끄러짐(FAIL 유발 설계 가능).
- **틈 통과 규칙**: void 폭 < 차길이 × 0.8 → 관성 점프 통과 허용, 이상이면 추락 = FAIL.
- **천장 충돌**: 차 상단 y > `c(x)`인 구간 진입 시 진행 불가/FAIL.
- 주행 방향: 항상 좌→우(단방향). 플레이어는 차를 직접 조작하지 않음.

### 4.6 상태 머신 / 실패 처리
- 상태: `PLAN → GO → (CLEAR | FAIL)`. FAIL/CLEAR에서 PLAN으로 즉시 복귀.
- 실패 시 **물체 배치 유지**(재시도 마찰 최소화). CLEAR 시 다음 레벨.

## 5. 레벨 디자인 문법 (퍼즐 프리미티브)

1. **갭 메우기** — 빈 공간을 그림자로 정확히 잇기 (코어 학습)
2. **깊이→길이 제어** — 점광원에서 물체를 광원 쪽으로 밀어 그림자 길이 확보 (원근 발산)
3. **회전→경사로** — 긴 물체를 회전시켜 램프/점프대 생성
4. **합성 길** — 둘 이상 그림자를 겹쳐(envelope) 긴 연속 도로 완성
5. **고정 그림자 = 주어진 지형** — 일부 길이 미리 주어짐, 빠진 구간만 정확히 연결(정렬 퍼즐)
6. **고정 그림자 = 장애물** — 고정 그림자가 천장/벽(`role:"ceiling"`), 그 밑으로 길을 내거나 우회
7. **실루엣 정밀** — 노치 형상을 회전시켜 정확한 틈/형태를 만드는 정밀 배치

## 6. 7레벨 명세

| L | 광원 | 가동 물체 | 고정 그림자 | 목표 배치 | 도입 프리미티브 | 클리어 조건 |
|---|---|---|---|---|---|---|
| L1 | 방향광 | 막대 ×1 | 없음 | 시작과 동일 높이, 중간 1개 갭 | ① 갭 메우기 | 막대 그림자로 갭을 이어 차 통과 |
| L2 | 점광원 | 막대 ×1 | 없음 | 넓은 단일 갭 | ② 깊이→길이 | 물체를 광원 쪽으로 밀어 그림자 확대 후 연결 |
| L3 | 점광원 | 긴 막대 ×1 | 없음 | 시작보다 높은 단 | ③ 회전 램프 | 막대 회전으로 경사로, 차 등판 |
| L4 | 점광원 | 막대 ×1 | 고정 막대 = 길 전반부 | 고정 끝에서 이어지는 후반 갭 | ⑤ 고정=지형 | 가동 그림자를 고정에 정확히 접속 |
| L5 | 점광원 | 막대 ×2 | 고정 블록 = 낮은 천장(ceiling) | 천장 아래 좁은 통로 너머 | ⑥ 고정=장애물 | 천장에 막히지 않는 낮은 길 구성 |
| L6 | 점광원 | 막대 ×2 + 삼각 ×1 | 없음 | 긴 공백 + 중간 추락 위험 | ④ 합성 길 | 복수 그림자 envelope으로 장거리 도로 |
| L7 | 점광원 | 막대 ×2 + 삼각 ×1 + 노치 ×1 | 고정 막대 ×1 | 다단 고저차 + 정밀 틈 | ②③④⑤⑦ 결합 | 전 요소 결합 — 영상 피날레 쇼피스 |

> L7은 난도보다 **시각적 카타르시스 우선**: "Go" 한 번에 차가 우아하게 목표까지 주행하는 장면을 영상 클라이맥스로.

## 9. 기술 아키텍처 (모듈 경계)

```
project/
  index.html              # importmap + 진입점
  vendor/three.module.js  # 로컬 vendored (three@0.159.0)
  src/
    main.js               # 부트스트랩
    core/                 # 렌더 무관, 순수·단위테스트 가능 (Three.js import 금지)
      mathx.js            # 투영 행렬·envelope 헬퍼
      ShadowProjector.js  # 오클루더+광원 → 벽 평면 convex 그림자 폴리곤[]
      ColliderBuilder.js  # 폴리곤[] → floor h(x) / ceiling c(x) heightfield (envelope)
      CarSimulator.js     # heightfield + 추력/중력 → 차 상태·CLEAR/FAIL
      GameStateMachine.js # PLAN↔GO↔CLEAR/FAIL 전이
    io/LevelLoader.js     # 레벨 JSON 파싱·검증
    ui/InteractionController.js  # PLAN 드래그·회전 입력
    render/Renderer.js    # Three.js 씬·라이팅·그림자 프리뷰·UI
  levels/L1.json ... L7.json
  test/                   # core 모듈 헤드리스 단위테스트
  TermProject.pdf
```

| 모듈 | 책임 | 입력 → 출력 | 의존 |
|---|---|---|---|
| `LevelLoader` | 레벨 JSON 파싱·검증 | JSON → 씬 상태 | (없음) |
| `ShadowProjector` | 오클루더+광원 → 벽 그림자 폴리곤 | 오클루더·광원 → convex 폴리곤[] | mathx |
| `ColliderBuilder` | 폴리곤 → floor/ceiling heightfield | 폴리곤[] → `h(x)`,`c(x)` | mathx |
| `CarSimulator` | heightfield+추력+중력 → 차 상태·판정 | heightfield → 위치/CLEAR/FAIL | (없음) |
| `InteractionController` | PLAN 드래그·회전 입력 | 포인터 → 오클루더 변환 | — |
| `GameStateMachine` | 상태 전이 + 모듈 조율 | 이벤트 → 상태 | 위 모듈 |
| `Renderer` | Three.js 씬·라이팅·프리뷰·UI | 상태 → 화면 | Three.js |

`ShadowProjector`/`ColliderBuilder`/`CarSimulator`는 렌더와 무관하게 헤드리스 단위테스트 가능.

### 데이터 흐름
```
LevelLoader.json
  → ShadowProjector (정점을 광원 기준 벽 평면에 투영 → convex 폴리곤[])
  → ColliderBuilder (x 샘플마다 floor h(x)=상단 max, ceiling c(x)=하단 min, 미커버 void)
  → CarSimulator    (좌→우 등속추력+중력 적분, h(x) 주행, 등판 35°, void 폭<0.8·차길이 점프, ceiling 충돌=FAIL)
  → GameStateMachine(PLAN 중 Projector+Builder 실시간 재계산→프리뷰; GO 시 freeze 후 Simulator 구동)
```

## 10. 3인 분담 & 레벨 포맷

- 분담:
  - A — `mathx` + `ShadowProjector` + `ColliderBuilder` (그림자 수학·콜라이더)
  - B — `CarSimulator` + `GameStateMachine` + 차 물리 튜닝 + core 단위테스트
  - C — `LevelLoader` + 7레벨 콘텐츠 + `Renderer`/아트/영상
- 레벨 포맷(JSON) 스키마:

```json
{
  "id": "L4",
  "light": { "type": "point", "pos": [x, y, z] },
  "wall": { "width": W, "height": H },
  "start": [sx, sy],
  "goal": [gx, gy],
  "fixedOccluders": [
    { "shape": "bar", "role": "floor", "size": [w, h, d], "pos": [x, y, z], "rot": deg }
  ],
  "movableOccluders": [
    { "shape": "bar", "role": "floor", "size": [w, h, d], "spawn": [x, y, z],
      "allow": { "translate": true, "rotate": true } }
  ],
  "params": { "carSpeed": 4.0, "gravity": 9.8, "maxClimbDeg": 35, "gapPassRatio": 0.8 }
}
```
- `role` 기본값 `"floor"`. `light.type`은 `"directional"|"point"`(directional은 `pos`를 방향으로 해석).
- 비코더 팀원도 JSON으로 레벨 양산·튜닝 가능.
