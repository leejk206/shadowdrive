## 1. depth(깊이) 시스템 제거

**현상**: Shift+휠로 오클루더의 z(광원-벽 깊이)를 조절 가능. 거의 모든 점광원 레벨이 "물체를 광원 쪽으로 최대한 밀기"만으로 풀려, 퍼즐이 단조롭다.

**요구**:
- 오클루더의 z 조절(Shift+휠) 입력 제거.
- 오클루더는 **(x, y) 평면 이동 + z축 회전**만 허용.
- z(깊이)는 레벨 데이터에서 **고정값**으로 지정 (`spawn[2]`).
- "광원 접근 클램프"(`GameStateMachine`의 light-distance 제약) 관련 로직도 단순화/제거 검토.

**영향**:
- 점광원 발산은 여전히 작동(레벨 디자이너가 z를 조절해 그림자 크기 사전 결정).
- 사용자 조작 축이 줄어들어 퍼즐 본질이 **(위치 + 회전) 조합**으로 수렴.
- `InteractionController._wheel`의 shiftKey 분기 제거. README 조작표·SUBMISSION 체크리스트도 동기화.

## 2. 일부 오브젝트가 그림자 길이를 만들지 못함

**현상**: 특정 오브젝트(추정: 프리즘 또는 특정 회전각의 막대)가 의도한 만큼 그림자 길이/형태를 만들지 못한다.

**조사 필요**:
- `ShadowProjector.projectOccluder` — convex hull이 정점 투영만으로 만들어지므로, **세장형 막대를 z축 회전 후 z 방향으로 정렬**시키면 실루엣이 짧아지는 케이스 존재 가능.
- `primitiveVerts('prism', ...)` 의 정점 수(6) 과 회전(z축만 지원)에서 실루엣이 어떻게 변하는지.
- `polygonVerticalSpan` 의 보간 정확도(샘플링 누락이나 0폭 폴리곤).

**기대 동작**: 가용한 모든 오클루더는 z축 회전·평면 이동만으로 의미 있는 길이 변화를 만들어야 한다.

**액션**: 회귀 테스트(`test/shapes.test.js`, `test/shadowProjector.test.js`) 보강 + 실제 브라우저에서 어떤 케이스가 깨지는지 사용자가 캡처해주면 더 빠름.

## 3. 길(path) 흰색 표시 제거 — "그림자 = 도로 = 장애물"

**현상**: 현재 floor heightfield가 흰색 라인(또는 리본)으로 별도 시각화돼 길과 그림자가 분리돼 보임.

**요구**:
- 흰색 path 시각화 제거. 도로/장애물 표시는 **그림자 자체**(벽 평면에 맺힌 어두운 영역)로만 한다.
- 동일 그림자가 floor 역할이면 차가 그 위를 달리고, ceiling 역할이면 차가 그 밑을 통과한다.
- "여기가 길"이라는 메타 시각화 없음 — 플레이어가 그림자 형태만 보고 추론.

**구현 포인트**:
- `Renderer.renderHeightfield` 의 라인/리본 출력 제거.
- 대신 벽 평면에 **그림자 폴리곤 자체를 어둡게 채워서** 렌더(섀도우 캐스팅 대신 폴리곤 직접 fill 가능).
- floor/ceiling role은 데이터에는 남아 있되 시각적으론 구분 없이 동일 톤의 그림자로 표시(혹은 미세한 톤 차이만).

## 5. 회전으로 다양한 실루엣을 만드는 기하 오브젝트 (요-사용자결정)

**요구**: 회전 각도에 따라 **여러 다른 실루엣**이 나오는 비-자명한 모양의 오클루더를 도입. 이것을 회전시켜 정확한 길/장애물을 만드는 것이 퍼즐 코어가 됨.

**모호한 부분 (사용자 결정 필요)**:
- **모양 후보**: L-블록 / T-블록 / 노치(직사각형에서 사각 홈) / 십자 / 가위표 / 임의 다각형 / 별모양 등 무엇을 채택할지.
- **개수**: 새 shape 1개 추가 vs 여러 개 도입.
- **회전 축**: 현재 z축 회전만 지원. x/y축 회전도 허용할지 (그러면 정점 수가 늘고 그림자 변동성 ↑, 하지만 조작 UX·구현 비용 ↑).
- **convex vs concave**: 현재 envelope 알고리즘은 convex 가정. 노치/L-블록은 compound(여러 convex part)로 표현 가능하지만, 그림자 union이 일반 polygon이 될 수 있어 `polygonVerticalSpan` 수정 필요.

**액션**: 사용자에게 모양·축·개수 결정을 받은 뒤 spec 확정.

## 6. 자동차 — 바퀴 + 경사 따라 차체 기울이기

**요구**:
- 현재 빨간 박스(BoxGeometry) 자동차에 **바퀴 메시** 추가.
- 주행 중 floor heightfield의 **로컬 경사**에 따라 차체가 자연스럽게 기울도록(피칭).
- 바퀴는 시각용. 물리는 그대로(점-on-line 모델 유지).

**구현 포인트**:
- `Renderer._makeCar` → Group으로 변경. 본체 + 바퀴 4개(또는 2개 가시).
- `Renderer.setCar(x, y)` 확장 → `setCar(x, y, slope)`. slope = floor의 dy/dx 근사. `Math.atan2(dy, dx)` 로 z축 회전(2.5D 정면뷰에선 화면 평면 회전).
- 바퀴는 주행거리 비례 자전(선택 — 시각 폴리시).
- cartoonCar FBX(plan Task 12)는 시간 부족 시 패스, 박스+원판 바퀴로 충분.
